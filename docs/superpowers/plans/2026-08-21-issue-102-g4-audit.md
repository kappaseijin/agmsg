# Issue #102 G4 Read-only Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execute inline; do not spawn additional agents.

**Goal:** Issue #102 の accepted decision に従い、G4 state pack v1 を exact roster と照合し、宣言された GitHub OPEN Issue scope の coverage を read-only で監査する `g4-audit` を Phase 1A として提供する。

**Architecture:** 既存の work-item contract/audit とは独立した `scripts/lib/g4-contract.js` と `scripts/lib/g4-audit.js` を Node.js 標準ライブラリだけで実装する。Bash wrapper は `g4-audit` の引数検証と roster JSON の受け渡しだけを行う。GitHub は明示的な GraphQL query の read-only 呼び出しで pagination し、coverage 集合と digest を canonical JSON から計算する。SQLite は開かず、ledger/current state は Phase 1B に延期する。

**Tech Stack:** Bash 3.2+, Node.js 標準ライブラリ（`child_process`, `crypto`, `fs`）, GitHub CLI GraphQL, SQLite-free Bats fixture tests。

**Spec:** `docs/decisions/2026-08-21T210215_issue-102-g4-implementation-design.md`

**Decision record:** `https://github.com/kappaseijin/agmsg/issues/102#issuecomment-5369510068`

## Global Constraints

- G4 pack の `schemaVersion`、scope、entry、basis、owner seat、workKinds、state、blocker、release predicate を fail-closed に検証する。
- scope は repository、`issueState: "OPEN"`、`labelsAll` のみを許可し、自由形式 GraphQL と暗黙の repository 全件取得を許可しない。
- scope ごとの live open Issue 集合を pagination 完了まで取得し、duplicate / missing / extra / count mismatch / cursor failure / GitHub failure は `unknown` として ready 根拠にしない。
- coverage 集合は `(repository, number)` の canonical sorted list として `coverageDigest` を決定的に計算する。
- entry の source 集合は coverage 集合と完全一致し、entry digest は `entryDigest` 自身を除いた canonical JSON の SHA-256 とする。
- `ready` entry は blocker を持たず、`blocked` entry は stable lower-snake-case `reasonCode` と v1 release predicate を持ち、`unknown` entry は blocker を持たない。
- Phase 1A では `g4-bootstrap`、`g4-transition`、`g4-pull`、G4 ledger/table/trigger、dispatch、GitHub write を実装・公開しない。
- `g4-audit` は SQLite を初期化・変更せず、GitHub write method / label mutation を呼ばない。
- README だけで Phase 1A の pack schema、command、output、state meaning、side-effect boundary、#97/#98 gate を理解できるようにする。
