# Issue #275 — `case.sh` 生成の参照解決設計

**producer（設計）: `agmsg_architect_claude`**
**実装: `agmsg_programmer_claude`（本書では実装しない）**
**formal reviewer: `agmsg_reviewer_claude`**
**README 影響: 無**

## 0. 結論（先に）

`tests/windows/lifetime_case.py` を新設し、`case.sh` の組み立てを次の 3 段にする。

| 段 | 内容 | 何を防ぐか |
| --- | --- | --- |
| **1. 推移閉包** | エントリ関数から**参照されるヘルパを再帰的に自動収録**する | 新しいヘルパが増えても手で足す必要がない。**#275 の再発を構造的に断つ** |
| **2. 未解決参照ゲート** | 解決できないヘルパ参照が 1 つでも残れば **`UnresolvedReference` を送出して生成を中止** | rc=127 として実行時に現れるのではなく、**生成時点で落ちる** |
| **3. 構文ゲート** | 組み立てた script を `bash -n` に通し、パースできなければ中止 | 切り出しの境界誤り（heredoc 等）を黙って通さない |

**「呼び先も一緒に切り出す」対症ではない。** 収録するヘルパの一覧はどこにも書かれず、
**ソースの参照関係から毎回計算される。**

**設計は実測で検証済み**（§5）。既存 2 試験は PASS し、負の対照 2 種は生成時点で KILLED した。

## 1. 現象と原因（実測で再現）

```
$ cd tests/windows && python3 -m unittest test_lifetime_adapter
FAIL: test_signal_wait_failure_suppression_is_preserved
  AssertionError: 127 != 0 : .../case.sh: line 15: _windows_native_diag_record_signal: command not found
FAIL: test_taskkill_failures_preserve_original_rc_and_output
  AssertionError: ... line 37 vs line 40: _windows_native_diag_record_taskkill: command not found
Ran 3 tests in 0.063s / FAILED (failures=2)
```

**Windows 依存ではない。** macOS で 0.06 秒で決定的に再現する。

原因は `test_lifetime_adapter.py` のローカルヘルパである。

```python
def function(source,name):
    start=source.index(name+'() {')
    return source[start:source.index('\n}\n',start)+3]
```

**対象関数 1 つだけをテキストで切り出す。** 呼び先は切り出されない。
不足分は `prefix` に**手書きされた stub 一覧**で埋めていた。

PR #259 が `_windows_native_diag_record_signal` / `_windows_native_diag_record_taskkill` を導入し、
対象関数がそれらを呼ぶようになった。**手書きの stub 一覧は更新されない。**
PR #266 のブランチは #259 のコミットを含んでいなかったため、
**PR 単体の CI では見えず、両者が main で合流した時点で初めて壊れた。**

```bash
git merge-base --is-ancestor 69573a8 61988c69   # -> NO
```

**これは「stub を 2 つ足せば直る」バグではない。** 手書きの一覧と、ソース側の呼び出し関係が
**同期していないこと**が原因であり、次のヘルパが増えれば同じ形で再発する。

### 2つ目の暗黙結合（本設計で併せて解消する）

`instrument()` は `test_codex_bridge_launcher.bats` の**文言そのもの**をアンカーにして置換する
（`replace('load test_helper', …)` 等）。アンカーが 1 個でなければ `ValueError` を送出する。
**こちらは既に fail-closed で守られている**（`test_unknown_source_rejected_before_adaptation`）。
本設計は同じ扱いを**参照の解決**にも与える。

## 2. 設計

### 2.1 新規モジュール `tests/windows/lifetime_case.py`

```
class UnresolvedReference(ValueError)

definitions(source)   -> {name: text}    fixture 内の関数定義
helper_refs(text)     -> {name}          コマンド位置に現れるヘルパ参照
external_helpers()    -> {name}          ソース外で解決される名前（§2.4）
build_case(source, entry, stubs, tail) -> str
```

`build_case` の処理:

```
1  defs = definitions(source)
   entry が defs に無ければ UnresolvedReference
2  stubbed = definitions(stubs) の名前集合
3  推移閉包: frontier=[entry]
     name を取り出し、stubbed に在れば飛ばす
     kept[name] = defs[name]
     helper_refs(defs[name]) のうち defs に在り stubbed でないものを frontier へ
4  script = "\n".join(kept.values()) + stubs + tail
5  未解決参照ゲート:
     missing = helper_refs(script) - set(kept) - stubbed - external_helpers()
     missing が空でなければ UnresolvedReference(missing)
6  構文ゲート: bash -n で script をパースし、rc≠0 なら UnresolvedReference
7  script を返す
```

### 2.2 出力順序 — stub は**閉包の後**に置く

```
[閉包で収録した実定義]
[stubs]              ← 後勝ちで実定義を意図的に上書きする
[tail: エントリ呼び出し]
```

bash は**後の定義が勝つ**。既存試験は `taskkill` / `_windows_native_bridge_pids` /
`_windows_native_wait_tasklist_gone` などを**意図的に差し替えて**振る舞いを固定している。
stub を先に置くと閉包が上書きしてしまい、**試験の意図が静かに壊れる。**

**stub は「収録しない」のではなく「収録したうえで上書きする」。**
これにより「stub 対象がソースから消えた」場合も未解決参照ゲートに掛かる。

### 2.3 `helper_refs` — コマンド位置のヘルパ参照

このリポジトリのシェルヘルパは例外なく `_[a-z][a-z0-9_]*` の形をしている。
**この命名規約を判定に使い、汎用のシェルトークナイザは書かない。**

```python
HELPER = re.compile(
    r'(?m)(?:^|&&|\|\||[;|(]|\$\(|`|\bif\b|\bthen\b|\belse\b|\bdo\b|\buntil\b|\bwhile\b)'
    r'\s*(?:!\s+)?(_[a-z][a-z0-9_]*)(?![=\w])')
```

| 要素 | 理由 |
| --- | --- |
| `(?![=\w])` | `_r=...` のような**変数代入を除外**する |
| `\$\(` と `` ` `` | `x="$(_helper …)"` の形の呼び出しを拾う。**§5.3 の実測で必要と判明した** |
| `[;\|(]` `&&` `\|\|` | `(source lib; _helper …)` やパイプラインの先頭を拾う |
| `_[a-z]` に限定 | 埋め込まれた PowerShell（`Get-CimInstance`、`Write-Output`）や awk プログラムを**誤って拾わない** |

#### なぜ汎用トークナイザを採らないか（実測に基づく）

試作でコマンド位置を汎用に解析する版を書いたところ、`_windows_native_diag_snapshot` が
**単一引用符で囲んだ複数行の PowerShell を `$( )` の中に含む**ため、引用の対応付けを誤り、
`Get-CimInstance` `Where-Object` `Pid` などを「未解決コマンド」として 10〜16 件報告した。
**fail-closed 設計では、この偽陽性がそのまま生成の停止になる。**

**判定を命名規約に寄せることで、引用の解析そのものを不要にした。**

### 2.4 `external_helpers()` — ソース外で解決される名前

fixture は自分が定義していないヘルパも呼ぶ。次の 3 経路がある。

| 経路 | 例 | 収集元 |
| --- | --- | --- |
| `load test_helper` | `_agmsg_*` | `tests/test_helper*.bash` |
| `source "$SCRIPTS/lib/…"` を伴う部分シェル | `_agmsg_pid_alive_local` | `scripts/lib/*.sh`、`lib/*.sh` |
| adapter が注入する観測フック | `_lifetime_emit` 等 | `tests/windows/lifetime-adapter.sh` |

これらのファイルから関数定義名を集め、**既知として扱う**（実測 281 件）。

> **限界（明記する）**: この集合は**実際に source されたか**までは検証しない。
> 「どこかで定義されている」ことしか示さない。ここを厳密にすると、部分シェル内の
> `source` を静的に追跡する必要があり、費用に見合わない。
> **未解決参照ゲートの目的は「ソースに存在しない名前を呼んでいないか」であり、
> スコープの検証ではない。**

### 2.5 `test_lifetime_adapter.py` の変更

- ローカルの `function()` を削除し、`lifetime_case.build_case` を使う
- `prefix` は `stubs` としてそのまま渡す（**中身は変更しない**）
- サブプロセスの環境から `AGMSG_WINDOWS_DIAG_*` を**除去する**

最後の点は新しい要求である。閉包により `_windows_native_diag_append` などの**実定義**が
`case.sh` に入るようになるためである。これらは

```bash
[ -n "${AGMSG_WINDOWS_DIAG_FILE:-}" ] || return 0
```

で早期に戻るため、**環境変数が未設定である限り副作用を持たない。**
呼び出し側の環境が汚れていると診断ファイルへ実際に書き込むので、**明示的に落とす。**

### 2.6 新規試験 `tests/windows/test_lifetime_case.py`

| 種別 | 内容 | 期待 |
| --- | --- | --- |
| 正の対照 | 現行 fixture で `build_case` が成功し、`_windows_native_diag_record_signal` の**定義本体**を含む | PASS |
| 正の対照 | 閉包が stub 対象の実定義も収録し、**stub がその後に置かれている**（出力順序） | PASS |
| **負の対照 A** | 対象関数へ未定義の呼び出し `_qqzz_absent_helper "$pid"` を足す | **`UnresolvedReference`。`case.sh` は生成されない** |
| **負の対照 B** | `_windows_native_diag_append` の定義をソースから削除する | **`UnresolvedReference`** |
| 負の対照 C | エントリ名が存在しない | `UnresolvedReference` |
| 負の対照 D | 構文が壊れた定義を与える | `UnresolvedReference`（`bash -n` 由来） |

**A は breaker が指定した受入条件そのものである。**
`rc=127` で実行時に落ちるのではなく、**生成の時点で例外になること**を確かめる。

## 3. 受入条件との対応

| breaker 指定の条件 | 本設計での実現 |
| --- | --- |
| 「呼び先も切り出す」だけの対症で終わらせない | **収録一覧を持たない。** 参照関係から毎回計算する（§2.1 の 3） |
| 未解決参照が残ったまま `case.sh` を生成しない | **`build_case` はファイルを書かない。** 呼び出し側が書く前に例外で止まる（§2.1 の 5） |
| 負の対照で生成時失敗を実測 | 負の対照 A / B。**実測済み**（§5.2） |

**`build_case` が「文字列を返すだけで書き込まない」ことが重要である。**
書き込みと検査を同じ関数に置くと、「壊れた `case.sh` が残ってから例外」になりうる。

### 5.3 設計の途中で検査自身が偽陰性を返した（記録する）

`helper_refs` の初版は行頭・`;`・`&&` の後だけを見ていた。この版では

```bash
root_key="$(_windows_native_diag_root_key "$root")"
```

を**拾えず、未解決参照ゲートが素通しした。** `case.sh` は生成され、実行時に

```
case.sh: line 220: _windows_native_diag_root_key: command not found
```

で落ちた。**#275 と同じ形の失敗を、それを防ぐはずの検査が見逃した。**

正の対照（既存試験の stderr 比較）が非一致を返したことで気づいた。
`$\(` と `` ` `` を命令位置として追加し、以後 §5.1 の一致に至った。

**この経緯は「検査を書いたら、在ると分かっている 1 件を掛けて検出できることを確かめる」
という規約の実例である。** 実装時も同じ手順を踏むこと。

### 5.4 収録される定義の規模

| エントリ | 直接参照 | 推移閉包（2 段目まで） |
| --- | --- | --- |
| `_windows_native_reap_bridge_root` | 5 | +7 |
| `cleanup_windows_native_processes` | 2 | +4 |

fixture の全 51 定義のうち収録されるのは十数件で、`case.sh` は小さいまま保たれる。

> **全定義を無条件に収録する案は棄却した。** 実測で `bash: syntax error` になった。
> `'\n}\n'` を終端とする切り出しが、heredoc を含む一部の関数で境界を誤るためである。
> **閉包に必要な関数はいずれもこの誤りに当たらない**が、境界の誤りを黙って通さないために
> `bash -n` ゲート（§2.1 の 6）を残す。

## 6. 実装者への申し送り

1. `lifetime_case.py` を新設し、`test_lifetime_adapter.py` からローカル `function()` を削除する
2. **stub は閉包の後に置く**（§2.2）。順序を逆にすると試験が静かに壊れる
3. `helper_refs` の正規表現は §2.3 のとおり。**`$(` を落とさないこと**（§5.3）
4. サブプロセス環境から `AGMSG_WINDOWS_DIAG_*` を除去する（§2.5）
5. `build_case` は**文字列を返すだけ**にする。ファイル書き込みを内部で行わない
6. **`stubs` の名前抽出に `definitions()` を使わないこと。**
   `definitions()` は `'\n}\n'` を終端とする切り出しであり、**1 行完結の stub
   （`_lifetime_begin() { :; }` 等）には一致しない。** 適用すると `stubbed` が空集合になり、
   閉包が stub 対象の実定義で上書きしてしまううえ、未解決参照ゲートが偽陽性を返す。
   **stub 側は定義名だけを拾う正規表現を使う。**

   ```python
   stubbed = {m.group(1) for m in DEF.finditer(stubs)}   # 本体は切り出さない
   ```

   > 試作でこの誤りを実際に踏んだ（`ValueError: substring not found`）。
   > reviewer も独立に、既存 stub 7 種が `'\n}\n'` 終端では **1 件も検出できない**ことを実測している。
   > §2.6 の正の対照（stub が閉包の後に置かれていること）が実装時にこれを検出する構造になっているが、
   > **先に知っていれば踏まない罠なので明記する。**
7. `test_lifetime_case.py` の負の対照 A / B は**必須**。KILLED を報告する
8. 変更後、`cd tests/windows && python3 -m unittest discover -p 'test_lifetime_*.py'` の
   全件 PASS を実測で示す
