# 観測結果を型で運ぶ（Issue #274 再設計）

## 0. 問いと答え

**問い（breaker 指定）**

> `wait_for` のタイムアウトを、呼び出し側が無視できない形にできるか。
> できるなら、静的検査は不要になるか。

**答え: できる。静的検査は不要になる。**

**`ast` 走査を削除したうえで、M5〜M11 相当の変異が実行時に落ちることを実測した**（§3）。
**そして、前回の過剰検出（M5 = `and` narrowing）は落ちない。**

---

## 1. 何を撤回するか

**前設計（`2026-09-06T170000_...` の §1.3.2 / §1.3.4 / §1.4）を撤回する。**

| 前設計 | 撤回する理由 |
| --- | --- |
| `evaluate(instances, correlation, polled=True, observed=True)` — **fail-open な既定値** | 呼び忘れが静かに通る。既定値そのものが穴だった |
| `ast` 走査で「戻り値を捨てていないか」を検査する | **構文では「値が判断に届いたか」を近似しきれない**（§2） |

**前設計は、穴を空けたうえで、その穴を検査で塞ごうとしていた。**
**穴を空けなければ検査は要らない。**

---

## 2. 静的検査が両方向へ外れた事実

実装 1 巡と verifier の 3 回の独立実測で、`ast` 走査は**両方向へ外れた。**

| 段階 | 結果 |
| --- | --- |
| 1 回目 | **M6 / M7 / M8**（判定への配線漏れ・偽装）が **SURVIVED**（検出漏れ） |
| 1 巡目修正 | M6 / M7 / M8 は KILLED。**しかし M5**（前設計が明示的に許可した `and` narrowing）が**誤って落ちた**（過剰検出） |
| 自主追加修正 | **M9 / M10**（証跡フィールドのリテラル化・取り違え）を発見・修正。**M5 の過剰検出は未解消** |

breaker の見立てを引く。

> 両方向に外れているということは、「値が判断に届いたか」を構文の形で近似しきれていないということである

**同意する。** `ast` は「`wait_for(...)` が式文かどうか」しか見ていない。

- 受けてから捨てる（`x = wait_for(...)` で `x` を使わない）は式文ではないので**通る**
- `and` で narrowing してから使うのは正しいのに、形が違えば**落ちる**

**近似の精度を上げても、この 2 方向は残る。**

---

## 3. 設計

### 3.1 範囲

**`scripts/issue253_actas.py` の `wait_for` / `evaluate` 経路のみ。**

- **`issue253_public_path.py` の `wait_for` 本体を変更しない**
- **同ファイルの他 6 箇所の呼び出しを変更しない**
- 共通ライブラリ化・他ファイルへの展開をしない

**したがって新しい型は `issue253_actas.py` の中に置く。**
`wait_for` は `bool` を返したままである。

### 3.2 考え方

**観測結果を `bool` のまま `evaluate` へ渡さない。**
`issue253_actas.py` の中で `Observation` に包み、**`evaluate` は `Observation` しか受け取らない。**

1. **`evaluate()` の観測引数を必須にする**（既定値を置かない）
2. **`evaluate()` は `Observation` 以外を拒む**
3. **`Observation` は `observe_until` 以外から作れない**
4. **`Observation` は自分がどの観測かを名前で持ち、取り違えを拒む**

**「呼ばれたこと」ではなく「その観測の結果が判定へ入ったこと」を、引数の型で成立条件にする。**

### 3.3 実装の骨格（`scripts/issue253_actas.py` へ足す）

```python
_TOKEN = object()


class Observation:
    """A named bounded-wait result. Only observe_until constructs it."""
    __slots__ = ('label', 'reached')

    def __init__(self, label, reached, _key=None):
        if _key is not _TOKEN:
            raise TypeError('Observation is constructed by observe_until only')
        self.label = label
        self.reached = reached

    def __bool__(self):
        return self.reached


def observe_until(label, predicate, seconds):
    """Wrap wait_for so the outcome cannot reach a verdict as a bare bool."""
    return Observation(label, wait_for(predicate, seconds=seconds), _TOKEN)


def require(observation, label):
    """Unwrap the named observation, or refuse. No default, no coercion."""
    if not isinstance(observation, Observation):
        raise TypeError(f'{label}: expected Observation from observe_until, '
                        f'got {type(observation).__name__}')
    if observation.label != label:
        raise TypeError(f'expected observation {label!r}, got {observation.label!r}')
    return observation.reached
```

呼び出し側（79 行・84 行）:

```python
polled = observe_until('watch_poll', lambda: all(
    (root / f"tmp/poll.{i['host_pid']}").exists() or h[0].poll() is not None
    for i, h in watches), 10)
item = f.send("actas-same" if same_sid else "actas-different")
observed = observe_until('handoff', lambda: any(
    item[0] in Path(str(h[2]) + ".stdout").read_text() for _, h in watches), 5)
```

**`seconds` は現状のまま（10 / 5）。値を上げない。**

判定:

```python
def evaluate(instances, correlation, polled, observed):
    if not require(polled, 'watch_poll') or not require(observed, 'handoff'):
        return "unknown"        # 観測窓に入らなかった。事象の有無は言えない
    ...                         # 以降は現状のまま
```

証跡:

```python
return {"role_ownership": ownership(instances),
        "role_path": evaluate(instances, correlation, polled, observed),
        "watch_poll_reached": polled.reached,
        "handoff_observation_reached": observed.reached,
        ...}
```

**`.reached` を明示する。** `json.dumps` は `Observation` を直列化できないため、
書き忘れれば `TypeError` で落ちる。**静かに壊れない。**

### 3.4 何がどう成立しなくなるか

| 誤った書き方 | どうなるか |
| --- | --- |
| 引数を渡し忘れる（M6 / M7 / M8） | **`TypeError: missing 2 required positional arguments`** |
| リテラル `True` を渡す（M9） | **`TypeError: expected Observation ..., got bool`** |
| **`wait_for` を直に呼んで渡す** | **同上。`Observation` に包まれていない** |
| 2 つを取り違える（M10） | **`TypeError: expected observation 'watch_poll', got 'handoff'`** |
| `Observation` を捏造する（M11） | **`TypeError: constructed by observe_until only`** |
| **`and` で narrowing する（M5）** | **通る。落ちない** |

**M5 が落ちないことが合格判定の要点である。**
**検査そのものが無いので、過剰検出は構造的に起こりえない。**

## 4. 実測（正・負の対照つき）

**試作で 11 件を実行した。静的検査は一切書いていない。**

```
POS  normal:                pass
POS  timeout->unknown:      unknown
M5   and-narrowing:         True
M6/7/8 omit arg:      KILLED TypeError: evaluate() missing 2 required positional arguments: 'polled' and 'observed'
M9   literal True:    KILLED TypeError: watch_poll: expected Observation from observe_until, got bool
M9b  raw wait_for result: KILLED TypeError: watch_poll: expected Observation from observe_until, got bool
M10  swapped:         KILLED TypeError: expected observation 'watch_poll', got 'handoff'
M11  forged:          KILLED TypeError: Observation is constructed by observe_until only
JSON .reached:        {"watch_poll_reached": true}
COPY deepcopy:        Observation('watch_poll',True)
PICKLE:               Observation('watch_poll',True)
```

### 4.1 対照の設計

**「疑っている失敗モードから対照を選ぶ」**（`development.rule.md`）に従った。

| 疑った失敗モード | 対照 | 結果 |
| --- | --- | --- |
| 検出漏れ（前回 M6/M7/M8） | 引数を落とす | KILLED |
| 検出漏れ（前回 M9/M10） | リテラル化・取り違え | KILLED |
| **過剰検出（前回 M5）** | **`and` narrowing** | **落ちない**（意図どおり） |
| 仕掛けの迂回 | `wait_for` を直に渡す／型を捏造する | KILLED |
| **常に落ちるだけではないか** | **正の対照 2 件** | **`pass` と `unknown` を返し分けた** |
| 既存試験を壊さないか | `copy` / `pickle` | 両方とも通る |

**`POS timeout->unknown` が要である。** 「何でも落ちる」のではなく、
**タイムアウトのときだけ `unknown` へ落ちる**ことを示している。

**`COPY` / `PICKLE` は、`tests/test_issue253_actas.py` が `copy` を import しているため確認した。**

### 4.2 合格判定への対応

breaker の合格判定は次のとおりだった。

> **成功**: 静的検査を**削除**したうえで、M5〜M10 相当の変異が**実行時に**落ちることを示せる

| 条件 | 結果 |
| --- | --- |
| 静的検査を削除したか | **削除した。試作に `ast` は 1 行も無い** |
| M6〜M10 が実行時に落ちるか | **すべて `TypeError`（§4）** |
| M5 が落ちないか | **落ちない** |

**成功と判定する。**

### 4.3 この試作の限界

- **実コードへ適用していない。** 試作は独立した小さな再現である
- `ThreadPoolExecutor` 越しの受け渡しなど、実際の呼び出し文脈は再現していない
- **`deepcopy` は `_TOKEN` の検査を通らずに複製できる**（`__reduce_ex__` が `__init__` を経由しないため）。
  **既存の `Observation` からしか複製できないので偽造の経路にはならないが、
  「`observe_until` 以外から作れない」は厳密には `__init__` 経由に限った主張である**

## 5. 実装者への申し送り

1. `scripts/issue253_actas.py` へ `_TOKEN` / `Observation` / `observe_until` / `require` を足す
2. 79 行・84 行を `observe_until(...)` にする。**`seconds` は 10 / 5 のまま**
3. `evaluate()` の引数を**必須**にし、`require()` で開く。**既定値を置かない**
4. `observe()` の戻り値へ `watch_poll_reached` / `handoff_observation_reached` を
   **`.reached` で**足す
5. **`ast` 走査の試験を作らない。** `feat/issue-274-wait-for-timeout-visible`
   ブランチに在るなら**消す**
6. `tests/test_issue253_actas.py` の既存試験は `evaluate(instances, correlation)` の
   2 引数で呼んでいる。**`observe_until` で作った `Observation` を渡す形へ直す。**
   **既定値を足して回避しないこと。それが今回撤回した穴である**
7. §4 の 11 件を実行し、**三値**（`KILLED` / `KILLED-BY-TSC` / `SURVIVED`）で報告する。
   **`POS` 2 件と `M5` は落ちてはならない。** 落ちたら過剰検出であり、設計の失敗である

**`issue253_public_path.py` を変更しないこと。** `wait_for` は `bool` を返したままでよい。

### 5.1 前回の失敗を繰り返さないために

**検査を足したら、正しい書き方が落ちないことも確かめる。**
`development.rule.md`「壊した状態 → 落ちる／正しい状態 → 通る」の両方向である。

**前回はここが抜けた。** M6/M7/M8 を KILLED にすることに集中し、
**M5 が落ちるようになったことに気づかないまま次へ進んだ。**
