# 副作用のないactas owner公開照会

## 主張・訂正・範囲

agmsg提供側の既存owner読取・生存確認を活かし、認可consumerが正常不存在・owner・stale・不正・読取不能・競合不明を区別できる公開契約を定める。
公式にowner照会手段が皆無なのではない。
公式cutoffのdoctorはread-onlyでownerとalive/STALEを表示するが、空ownerをlock=noneへまとめ、診断上の表示省略も行う。
`actas_lock_owner`は非regular pathと不存在を空にし、先頭行だけを読むため、その出力単体で認可上の不明を区別できない。
このソース上の観測を認可契約へ置き換えることが本書の一主張である。

PM generation/pidStart/binding、role/kind、account、独自policyはagguild側に残す。
message claim/ackは別概念であり、B3や公式PR #372をactas owner解決に転用しない。
設計と適合試験パッチ構成のみを記載し、実装・上流投稿・本番照会のためのclaim操作は行わない。

## 方式比較

| 方式 | 評価 |
| --- | --- |
| doctorの表示をparse | 省略・redaction・空値の意味が認可と異なるため不採用 |
| actas-claimを呼んで結果を見る | claim/rollback等の副作用を生むため禁止 |
| consumerが内部claimを読む | 外側schema readerになるため不採用 |
| 提供側に厳格read-only resourceを追加 | 推奨。doctorと既存lock helperの責務を活かし、正常/不明を別返却 |

提案commandは`api.sh get teams <team> actas-owner <agent> --schema-version 1`とする。
既存doctorの人向け出力、既存actasのwriter/owner/state/release/GCの契約は変更しない。
提供側に構造化観測helperを追加し、既存path encodingとinstance生存確認を再利用する。
既存`actas_lock_owner`の空出力だけをラップして新契約を満たしたことにはしない。

## schemaと終了状態

一行JSONのenvelopeに`schemaVersion:1, resource:"actas-owner", team, agent, status, reason, owner, ownerKind, liveness, consistency`を持つ。
ownerはopaque tokenであり、正常に読めた場合だけ返す。不正fileの内容を診断ログへ出さない。
ownerKindは`composite`または`legacy`、値がないときはnullとする。
livenessは`alive`、`dead`、`unknown`、またはownerなしのnullとする。
consistencyは成功時`observed`、不明時`unknown`とし、予約・lease・永久の所有権を意味させない。

| 条件 | status / reason | exit |
| --- | --- | --- |
| 正常ownerが読め、生存を確認 | owned / null、liveness=alive | 0 |
| 正常ownerが読め、死亡を確認 | stale / owner_dead、liveness=dead | 0。削除・再claimしない |
| 登録targetは存在し、claimが正常に不存在 | absent / claim_absent、owner=null | 0。認可の許可にはしない |
| team/agentの正常な登録不存在 | not_found / target_not_found | 1 |
| 空・不正encoding・型/構文不正・非regular claim | unknown / claim_invalid | 1 |
| claim/親path/登録の読取不能 | unknown / read_failed | 1 |
| 読取中のowner/path/登録変更を検出 | unknown / concurrent_change | 1 |
| 生存確認に必要な情報を取得できない | unknown / liveness_unavailable、liveness=unknown | 1 |
| 未対応版・不正引数 | error / unsupported_schema_versionまたはinvalid_argument | 2 |

exit0は正常観測を意味し、認可成功ではない。
consumerはownedと期待ownerの完全一致を確認し、独自のprocess開始token等も照合する。
同SID別PIDは異なるownerである。SIDだけに短縮して一致判定しない。
legacy bare SIDは既存提供側が有効tokenとして扱うものに限りlegacyとして表示する。
PM consumerはlegacyを認可しないが、API全体から既存形式を消すことはしない。

tokenの検証は提供側writer/instance形式に従い、UTF-8・一つのowner・最大長の契約を明示する。
writerの通常出力はowner＋LFである。末尾LFなしのlegacy単行を受理する場合も同じownerとして返し、空・追加行・制御文字は不正とする。
このlegacy許容はPM側の既存#243 file parserをそのまま外部APIとして露出することではない。

## 観測アルゴリズムと限界

1. team/agentを検証し、提供側の登録readerで対象の正常な存在を確認する。破損を不存在に変換しない。
2. 正式path生成helperを使う。親directoryの到達不能とENOENTを区別する。symlinkやdirectory等の非regularなclaimはunknownとする。
3. sourceを識別して内容を読取り、全体の形式を検証する。開くまでの置換やread失敗は分類して返す。
4. 提供側instanceの既存生存確認を用いる。ただし保守的に「死んでいないと仮定」する失敗は、認可観測ではaliveと断定せずunknownとする。必要な区別は提供側helperの観測用variantへ閉じ込め、既存writerの回収判断を変更しない。
5. owner/pathと対象登録の変化を返却前に再確認し、検出した競合はunknownとする。消失→出現も同様。自動再試行で別ownerへ追従しない。

不存在は正常な親pathの確認と再確認の間に同じ不存在を観測できた場合に限る。
権限エラーを単なるfile testのfalseで不存在へ変換しない。
一つのsnapshot観測であり、同値へ戻るABAや返却後の変更までは防げない。
観測tokenやTTLを発行して時間内の排他を約束しない。
厳密なtransaction認可が必要なconsumerは別の契約が必要で、本APIがその代わりとはしない。
PMは毎tool callでfreshに照会し、process bindingと突合する。署名・悪意ある同一OSユーザーへの防御も本APIの保証外である。

## 副作用禁止

照会はclaim/release/GC/join/reset、DB初期化・migration、role-session記録、engine/watch起動を呼ばない。
失敗時にも復旧を代行しない。
公式提供側の内部read helperだけを使い、外側agguildへfile path/schemaを要求しない。
read-onlyの受入では実質的な所有状態だけでなく、file作成・内容更新・新process・登録・DB/runtime更新がないことを確認する。
通常のOS read access-time更新の有無は環境依存として分離し、所有状態変更と混同しない。

## 提案パッチと適合試験

設計受入後のprogrammerは公式cutoffを基準に、`api.sh`新route、提供側の観測helper、`tests/test_api_actas_owner.bats`、READMEの公開利用説明を独立patchへまとめる。
doctor出力の書換えやPM binding移植は含めない。
#246とは別PRにし、共通helperを導入する場合も依存HEADと最小共有範囲を明示する。

| 対照 | 必須結果 |
| --- | --- |
| 既存正式writerで正常claim | owned、完全owner、生存。観測前後の所有状態不変 |
| 正常な不存在 | absent、exit0。正常empty teamや未登録targetとは区別 |
| 同SID別PID | 異なるownerとして出力。consumerのSID-only比較変異が落ちる |
| 死亡owner | stale、fileは残存。GCを呼ばない |
| 空file・追加行・不正byte・directory・symlink | unknown、認可不可。空→absent変異を検出 |
| 読取不能・親path権限不足 | unknown。実効ユーザーで読めないことを別対照で確認し、rootでchmodしただけを故障と呼ばない |
| 生存情報の取得失敗 | unknown。kill不可を即deadまたはaliveへ変換しない |
| readerの途中にbarrierを置きowner交換/削除/作成 | concurrent_change。単なるsleepで再現扱いにしない |
| 破損登録と正常未登録 | unknownとnot_foundを区別 |
| stdout/exit/副作用 | 全結果でschema整合、エラーに生内容なし。前後更新・engine起動0 |
| 旧CLI回帰 | doctor・actas・watch・release/GCの既存挙動が変わらない |

負の変異は「空→absent」「読取error→absent」「再確認削除」「照会後GC」「SIDだけ比較」を含む。
各変異を対応する試験が検出することが適合条件である。
独立実測は既存verifierの別context、受入判断はClaude reviewerが固定HEAD全差分に対して行う。
本書で試験PASSを主張しない。

## 提供・consumer受入

READMEにはcommand、schema/exit、read-only、正常観測と認可の違い、raceの限界、未対応版の挙動を自己完結で記す必要がある。
本設計段階ではREADMEや実装を変更しない。
P2の解除には公式提供版、固定契約、独立正負対照、agguild consumer統合受入がすべて必要である。
fork試作や未merge PR、#245の設計受入は提供の代替にならない。
公式採用時の契約変更は再設計・再受入し、旧内部file readerへ黙って戻さない。
